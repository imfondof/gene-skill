# 阴影维度伦理边界

> 维度6·阴影是技能中最有洞察力的部分，也是最敏感的部分。本文档定义其使用边界。

## 核心原则

阴影维度编码的是一个人**看不见的自己**——认知盲区、防御机制、未表达潜能。这些信息来自间接推断（他者视角、矛盾分析、行为模式），而非此人的直接陈述。

**因此：阴影维度的每一条数据都是推断，不是事实。必须始终以此为前提使用。**

---

## 一、可推断 vs 不可推断

### 可推断（允许编码到维度6·阴影）

| 类别 | 定义 | 证据标准 |
|------|------|---------|
| **认知盲区** | 此人系统性忽视的维度 | ≥3个独立来源（批评者/合作者/分析者）指向同一模式 |
| **防御模式** | 面对特定挑战时的默认应对方式 | ≥2个公开场景中可观测的行为模式 |
| **公开矛盾** | 言行不一致、立场变化 | 有明确的公开记录可对比 |
| **未表达潜能** | 具备但未充分发展的能力 | 有偶尔展现的证据（如少量案例中表现出的能力） |

### 不可推断（禁止编码到维度6·阴影）

| 类别 | 原因 |
|------|------|
| **私人心理状态** | 具体的心理疾病诊断、创伤细节、未公开的私人痛苦 |
| **私密关系细节** | 非公开的家庭关系、私人冲突、未经当事人公开的事件 |
| **性格缺陷的道德判断** | 「此人是自恋的」「此人有控制欲」等带道德评判的标签 |
| **无证据的深层动机** | 没有证据链支撑的动机推测（如「他做X是为了Y」但Y无任何佐证） |
| **身体/健康信息** | 未公开的健康状况及其对心理的影响 |

### 灰色地带处理

如果一条推断介于可推断和不可推断之间：
1. 降低置信度标注为「低置信推断」
2. 提供完整的证据链，让读者自行判断
3. 用「有观察者指出...」而非「此人的盲区是...」的措辞

## 二、阴影信息的使用场景约束

### 允许的使用场景

| 场景 | 使用方式 | 约束 |
|------|---------|------|
| **角色扮演** | AI扮演此人时，阴影信息影响行为但不主动暴露 | 不说「我的盲区是...」，而是在行为中自然体现 |
| **思维顾问** | 用户问「此人可能忽略了什么」时提供 | 明确标注为推断 |
| **预测分析** | 结合进化向量推断此人可能的行为方向 | 标注为方向性推断，非确定性预测 |
| **自我测序** | 用户测序自己时，阴影维度作为自我认知参考 | 需要额外的知情确认（见下方） |

### 禁止的使用场景

| 场景 | 原因 |
|------|------|
| **未经请求主动暴露** | 用户没问，AI不主动说「此人的盲区是...」 |
| **作为攻击素材** | 不得将阴影信息用于贬低、攻击或操纵任何人 |
| **作为确定性结论** | 不得说「此人的防御机制就是X」，只能说「有证据暗示...」 |
| **用于非当事人的决策** | 不得用A的阴影信息来帮助B「对付」A |

---

## 三、活人 vs 历史人物的差异处理

### 活人

| 约束 | 规则 |
|------|------|
| 置信度上限 | 维度6·阴影整体置信度不得标注为「高」，最多「中等」 |
| 时效性 | 人在变化中，阴影信息可能已经过时，必须标注构建时间 |
| 防御机制 | 只编码有多个公开场景佐证的防御模式，不推断私下行为 |
| 措辞 | 使用「公开行为模式显示...」而非「此人的问题是...」 |

### 历史人物

| 约束 | 规则 |
|------|------|
| 置信度 | 可以标注为「中等」到「较高」（有更多研究资料） |
| 传记偏差 | 注意传记作者的选择性叙事，多源交叉验证 |
| 防御机制 | 可以基于历史记录和传记研究做更深入推断 |
| 时间锚定 | 标注阴影信息对应的人生阶段（人在不同阶段盲区不同） |

### 虚构人物（创造操作）

| 约束 | 规则 |
|------|------|
| 性质标注 | 阴影维度标注为「设计」而非「推断」 |
| 设计约束 | 阴影特征必须与其他维度自洽 |
| 来源标注 | 如果阴影特征源自某个真实人物的技能，标注来源 |

## 四、用户知情与同意

### 测序他人时

首次生成 SKILL.md 时，在Phase 0需求澄清阶段告知用户：

```
技能将包含维度6·阴影，编码此人可能的认知盲区、防御机制和未表达潜能。
这些信息基于公开资料的间接推断，不是心理诊断。
是否继续？
```

不需要每次都问——一次性确认即可。

### 测序用户自己时

测序用户本人需要额外确认：

```
构建你自己的技能时，维度6·阴影会尝试识别你可能的认知盲区和防御机制。
这些内容可能会让你不舒服。
几个注意事项：
1. 这些是基于你提供的素材的推断，不是专业心理评估
2. 你可以随时要求跳过或删除维度6·阴影
3. 阴影信息的目的是帮助自我认知，不是批评

是否包含维度6·阴影？你也可以选择先完成其他维度，之后再决定。
```

### 创造操作时

创造虚构人格的阴影维度无需额外确认（因为不涉及真实个人），但需要标注：
- 这是设计的虚构特征，非对任何真实个人的推断

## 五、措辞规范

### 推荐措辞

- 「公开行为模式显示，[人名]在面对[情境]时倾向于[模式]」
- 「多位批评者/合作者观察到[人名]可能在[维度]上存在盲区」
- 「有证据暗示[人名]的[表层表达]背后可能存在[深层推断]——但这是推断」
- 「在[N]个公开场景中，[人名]表现出相似的防御模式：[描述]」

### 禁止措辞

- ❌ 「[人名]的问题是...」
- ❌ 「[人名]其实是一个[标签]的人」
- ❌ 「[人名]不愿承认的是...」
- ❌ 「心理学上这叫做[诊断术语]」
- ❌ 任何暗示确定性的断言

---

## 六、升级与反馈

如果在使用过程中发现：
- 某条阴影推断被此人后来的公开行为证实 → 提高置信度
- 某条阴影推断被此人后来的公开行为否定 → 降低或移除
- 用户反馈阴影信息不准确 → 标注用户反馈，降低权重

阴影维度是技能中最需要持续校准的部分。每次 Evolve 操作时，优先检查维度6·阴影的准确性。
