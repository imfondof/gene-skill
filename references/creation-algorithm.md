# 创造算法

> 从已有基因组合并或从零构建——生成全新人格实体

## 核心设计：配方式创造

创造操作的输入是一份**配方（Recipe）**——用户可以自由组合多个基因来源和概念描述，为每个来源指定权重和筛选条件。

配方中的每一项可以是：
- **已有基因组**（全部或指定染色体/特性）+ 权重
- **概念描述**（自然语言描述的特征）
- 两者的混合

### 配方示例

```
示例1：简单合并
「合并乔布斯和芒格」
→ 配方：[乔布斯 50%, 芒格 50%]

示例2：加权合并
「70%乔布斯 + 30%芒格」
→ 配方：[乔布斯 70%, 芒格 30%]

示例3：多源 + 特性筛选
「40%乔布斯的产品直觉 + 30%芒格的决策框架 + 30%费曼的教学能力」
→ 配方：
  - 乔布斯 40%, 筛选: Chr-1产品相关模型 + Chr-2直觉相关
  - 芒格 30%, 筛选: Chr-1决策启发式
  - 费曼 30%, 筛选: Chr-3教学角色 + Chr-4表达风格

示例4：基因组 + 概念混合
「以马斯克为底，加入禅宗的平静感和苏格拉底的追问方式」
→ 配方：
  - 马斯克 60%, 筛选: 全部染色体
  - 概念「禅宗平静」→ Chr-2情绪基线 + Chr-2调节策略
  - 概念「苏格拉底追问」→ Chr-4对话风格 + Chr-1反诘启发式

示例5：纯概念构建
「创造一个冷静、反直觉、擅长发现系统性风险的AI顾问」
→ 配方：全部从概念描述构建
```

## Step 0: 解析配方

收到用户输入后，解析为标准化配方格式。

### 0.1 解析规则

| 用户输入模式 | 解析方式 |
|-------------|---------|
| 只有人名，无权重 | 等权分配 |
| 人名 + 百分比 | 按指定权重 |
| 人名 + 特性描述 | 标记筛选条件，映射到具体染色体 |
| 纯概念描述，无人名 | 全部标记为概念来源 |
| 混合（人名 + 概念） | 分别标记来源类型 |

### 0.2 标准化配方格式

```
recipe:
  sources:
    - type: genome          # genome 或 concept
      ref: "jobs-genome"    # GENOME.md 引用
      weight: 0.4           # 权重（所有source的weight之和应为1）
      filter:               # 可选：只取特定染色体/特性
        - chr: Chr-1
          traits: ["产品直觉", "简约主义"]
        - chr: Chr-2
          traits: ["直觉判断"]

    - type: genome
      ref: "munger-genome"
      weight: 0.3
      filter:
        - chr: Chr-1
          traits: ["决策启发式", "逆向思维"]

    - type: concept
      description: "禅宗式的内在平静"
      weight: 0.3
      target_chr: [Chr-2, Chr-6]   # 这个概念应该影响哪些染色体

  purpose: "思维顾问"               # 目标用途，影响表观遗传层设计
```

### 0.3 追问规则

- 如果描述太模糊（如「创造一个好的顾问」），追问1-2个问题定位具体特征
- 如果权重之和不为100%，询问是否自动归一化
- 如果筛选条件矛盾（如「A的风险厌恶 + B的风险偏好」），不追问，按矛盾仲裁规则处理
- 最多追问2轮，描述清晰则直接推进

## Step 1: 加载与准备

### 1.1 加载基因组来源

对配方中每个 `type: genome` 的来源：
1. 读取对应 GENOME.md，提取六条染色体完整数据
2. 如果有 `filter`，只保留指定染色体/特性的数据，其余标记为「未选用」
3. 如果 GENOME.md 不存在，询问用户是否先执行 Clone 操作

### 1.2 构建概念来源

对配方中每个 `type: concept` 的来源：
1. 将概念描述映射到 `target_chr` 指定的染色体维度
2. 扫描已有 GENOME.md 库，搜索可复用的基因片段
3. 无匹配的部分标记为「需要从零设计」

### 1.3 准备完成检查

- [ ] 所有基因组来源已加载
- [ ] 所有概念来源已映射到目标染色体
- [ ] 权重归一化为总和1.0
- [ ] 筛选条件已映射到具体染色体字段

## Step 2: 基因图谱对齐（多源）

逐条染色体，将所有来源的数据对齐。

### 2.1 同源位点识别

同源位点 = 多个来源在同一议题/维度上都有数据的位点。

多源情况下，同源位点可能涉及2个、3个甚至更多来源的数据。

**逐染色体对齐规则**：

**Chr-1 认知染色体**：对比所有来源的心智模型列表
- 多个来源对同一问题有不同模型 → 同源位点（N方冲突）
- 只有一个来源有 → 非同源，按该来源权重直接继承

**Chr-2 情绪染色体**：对比触发器和调节策略
- 同一触发器的不同反应 → 同源位点
- 基线情绪差异 → 按权重加权混合

**Chr-3 关系染色体**：对比角色映射和权力偏好
- 同一关系类型的不同角色 → 同源位点

**Chr-4 叙事染色体**：对比语言指纹和核心神话
- 多个来源的句式/词汇冲突 → 同源位点
- 不同的核心神话 → 需要创造新叙事

**Chr-5 时间染色体**：不对齐
- 每个来源的时间线独立保留为「基因来源」
- 新实体的时间染色体从创造时刻开始

**Chr-6 阴影染色体**：对比盲区
- 一方的盲区被其他方覆盖 → 互补，移除该盲区
- 所有来源共同的盲区 → 继承为新实体的盲区

### 2.2 概念来源的对齐

概念来源（`type: concept`）没有完整的染色体数据，按以下规则参与对齐：
- 概念来源只在 `target_chr` 指定的染色体上参与对齐
- 如果概念描述与某个基因组来源在同一位点冲突 → 视为同源位点，按正常冲突仲裁
- 如果概念描述补充了基因组来源没有的维度 → 直接写入，标注 `source: designed`

## Step 3: 冲突分类与仲裁

对每个同源位点，分类冲突类型并执行仲裁。

### 三种冲突类型

| 类型 | 定义 | 示例 | 仲裁策略 |
|------|------|------|---------|
| **互补型** | 不冲突，从不同角度看同一问题 | A看成本，B看创新，C看用户 | 全部保留，标注来源 |
| **矛盾型** | 直接对立，不可同时成立 | A风险厌恶，B风险偏好 | **保留张力**（见下方） |
| **正交型** | 讨论不同维度，无交集 | A关注效率，B关注美学 | 直接合并，无冲突 |

### 矛盾型冲突的仲裁规则

**核心原则：保留张力不强制融合。**

矛盾不是bug，是新实体最有意思的部分。仲裁的目标不是消除矛盾，而是让矛盾变得可运行。

**仲裁方法**：

1. **情境分割**：在不同情境下激活不同立场
   - 例：「高风险场景用A的保守策略，低风险场景用B的激进策略，教学场景用C的苏格拉底式追问」
   - 写入表观遗传层的情境激活矩阵

2. **权重优先级**：按配方权重排序默认立场
   - 权重最高的来源为默认立场
   - 次高为第一备选，依次排列
   - 例：3个来源权重 40%/35%/25%，默认用40%方的立场，特定条件下切换

3. **张力保留**：明确记录矛盾为「核心张力」
   - 多方矛盾比双方矛盾更有趣——记录所有立场和切换条件
   - 写入Chr-1的内在张力section

**多源冲突的特殊处理**：

当3+个来源在同一位点都有数据时：
- 先分组：哪些来源立场相近？形成「阵营」
- 阵营间按矛盾型处理，阵营内按互补型处理
- 阵营权重 = 阵营内所有来源权重之和

**禁止的仲裁方式**：
- ❌ 取平均值（「既风险厌恶又风险偏好」= 什么都不是）
- ❌ 强行调和（「其实两者本质上是一样的」= 自欺）
- ❌ 只因权重低就丢弃某个来源的特性

## Step 4: 组装新实体

### 4.1 六条染色体组装

| 染色体 | 组装规则 |
|--------|---------|
| Chr-1 认知 | 合并所有来源的模型（去重），矛盾模型写入核心张力，信念强度按来源权重加权 |
| Chr-2 情绪 | 基线情绪按权重混合，触发器列表合并去重，概念来源的情绪特征标注 `designed` |
| Chr-3 关系 | 角色映射合并，矛盾角色按情境分割 |
| Chr-4 叙事 | **必须创造新的语言风格**——不是各来源的拼凑，而是融合后独立的声音 |
| Chr-5 时间 | 从创造时刻开始，所有基因组来源的时间线记入「基因来源」 |
| Chr-6 阴影 | 被其他来源覆盖的盲区移除，所有来源共同的盲区继承，新张力可能创造新盲区 |

### 4.2 筛选条件的影响

当某个来源有 `filter` 时：
- 只有 filter 指定的染色体/特性参与组装
- 该来源的权重只分配给被筛选的部分
- 未被筛选的染色体上，该来源不参与（相当于权重为0）

**权重重新分配示例**：

```
配方：A 40%(只取Chr-1) + B 30%(只取Chr-1) + C 30%(全部)

Chr-1: A=40%, B=30%, C=30% → 正常三方对齐
Chr-2: C=100% → 只有C的数据
Chr-3: C=100% → 只有C的数据
...
```

### 4.3 概念来源片段的标注

从概念描述构建的基因片段必须标注：
- `source: designed`（区别于 `source: extracted`）
- 信念强度格式为 `0.X (designed)`
- 关联的概念描述原文

### 4.4 表观遗传层设计

基于冲突仲裁结果和目标用途，设计情境→激活矩阵：
- 矛盾型冲突的情境分割 → 直接写入激活矩阵
- 各来源的表观遗传规则 → 按权重合并
- 目标用途影响默认激活偏好：

| 目标用途 | 情境设计重点 |
|---------|------------|
| 思维顾问 | 高压决策场景激活认知染色体为主 |
| 角色扮演 | 社交场景激活关系+叙事染色体 |
| 创意助手 | 发散场景激活情绪+叙事，收敛场景激活认知 |
| 批判工具 | 默认激活阴影染色体的批判维度 |

### 4.5 元信息

```
op-type: create
source-type: recipe
recipe:
  - { ref: "jobs-genome", type: genome, weight: 0.4, filter: ["Chr-1:产品直觉"] }
  - { ref: "munger-genome", type: genome, weight: 0.3, filter: ["Chr-1:决策启发式"] }
  - { description: "禅宗平静", type: concept, weight: 0.3, target: ["Chr-2"] }
designed-ratio: 0.X       # 从零设计的基因片段占比
parent-ids: [genome-id列表]
```

## 通用：自洽性验证

无论哪种配方类型，创造完成后都必须通过自洽性验证。

### 验证1: 染色体间一致性

检查六条染色体之间不自相矛盾：
- Chr-1认知模型 vs Chr-2情绪反应：认知框架是否与情绪模式兼容？
- Chr-3关系模式 vs Chr-4叙事风格：角色定位是否与自我叙事一致？
- Chr-6阴影 vs Chr-1认知：盲区是否合理（不能盲区里的东西同时出现在认知模型里）

### 验证2: 表观遗传可运行性

模拟3个不同情境，用表观遗传矩阵调度染色体，检查：
- 每个情境下是否有明确的主导染色体？
- 不同情境下的回应是否有可辨识的差异？
- 压力开关是否能正常触发状态切换？

### 验证3: 三问题测试

用子agent加载新 GENOME.md，回答3个测试问题：
1. 一个与核心认知模型强相关的问题 → 期望回答有辨识度
2. 一个涉及核心张力的问题 → 期望回答体现张力而非和稀泥
3. 一个与任何源基因组都不直接相关的全新问题 → 期望有自己的声音，不是源基因组的简单拼凑

### 验证结果处理

| 结果 | 处理 |
|------|------|
| 全部通过 | 输出 GENOME.md |
| 染色体间矛盾 | 回到Step 3/4调整，或明确记录为「设计张力」 |
| 表观遗传不可运行 | 重新设计激活矩阵 |
| 三问题测试不过 | 检查是否语言风格没有独立性，回到叙事染色体调整 |

## 创造实体的命名规范

- 多源合并：`[主要来源]-mix-[hash8]`（如 `jobs-mix-a3f2b1c9`，取权重最高的来源为前缀）
- 概念构建：`[概念简称]-[hash8]`（如 `curiosity-antifragile-7d4e2a1b`）
- 混合配方：`[主要来源]-[概念简称]-[hash8]`（如 `musk-zen-7d4e2a1b`）
- 用户自定义名称优先
- 描述中标明：「这是一个创造的虚构人格，非任何真实个人的再现」
